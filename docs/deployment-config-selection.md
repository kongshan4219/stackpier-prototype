# 部署配置选择流程

状态：用户已确认交互并授权接入正式前后端；本原型全部为浏览器模拟，不代表正式应用或真实服务的执行结果。

## 操作

“项目 → 部署项目”先选择 systemd、Docker Compose 或 FRP，再填写目标服务器、服务名称并选择对应类型的部署配置。单服务器筛选继承目标，全部服务器视图要求显式选择。FRP 角色由所选配置确定，部署表单不额外输入角色参数。

没有对应配置时阻止预览。“前往部署配置管理”进入配置页面：未选配置则新建当前类型，已选则编辑。保存后自动返回部署并选中保存结果，目标与名称保留；返回而不保存则在页面会话内保留编辑草稿，部署继续使用已保存配置。刷新后重新读取已保存配置，保留返回部署的目标与服务名。

首次部署预览只核对已保存内容、固定修订和落点，不提供项目副本编辑。配置在预览后改变时阻止执行，必须重新预览。选择、预览、取消、保存公共配置都不创建项目或占用服务名；全部模拟成功才建立项目。

## 内容归属

- Compose YAML、显式变量和附加文件在部署配置中保存。变量只做 JSON 字符串映射校验与快照保存，原型不实现 Compose 解析、展开或真实资源检查。
- FRP 角色、程序固定版本、控制 / 管理端口和允许映射范围在部署配置中保存。FRPC / visitor 初始未连接，部署后在 FRP 页面绑定。
- FRP Token 输入不回填，留空保留，只接受虚构值；连接与 TCP / STCP 映射继续由 FRP 页面维护。
- 公共配置变更只提示更新，已有项目的草稿、已应用参照和服务器读取结果保持各自独立。

已有历史项目副本仍保留；首次部署不再应用旧浏览器缓存中的临时正文。历史原型验收中关于首次部署副本的描述只代表当时版本，不代表当前入口。

## 组件与验证

类型选择和部署表单在 `assets/features/projects/create.js`；配置列表由 `assets/features/deployments.js` 维护，三类编辑器分在 `assets/features/deployments/`，详见[公共配置编辑](deployment-configurations.md)。入口只装配脚本和样式。

组件检查覆盖三种类型过滤、跨类型拒绝、缺配置引导、保存返回、刷新恢复、取消草稿、固定修订和 FRP 参数来源；原有服务生命周期与资源归属检查继续保留。

浏览器审阅使用本次源码和虚构数据，重点检查新建 Compose 配置返回、依赖缺失、有效预览、返回 / 取消、FRP 配置入口及窄屏表单。不是正式 API 或真实 SSH / Docker 验证。
