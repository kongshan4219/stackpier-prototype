# FRP 连接与部署

流程为“部署服务器角色 → 新增连接 → 应用连接配置”。页面顶部统一使用“部署 FRP”入口，保留角色选择，服务器使用单选下拉框，一次部署一台服务器，不提供批量部署。frpc / frps 可在没有连接时独立部署；visitor 仍按已有 STCP 连接配置部署。

FRP 页面默认展示连接清单，不设“服务器部署”子页面。统一从顶部“部署 FRP”入口选择角色和服务器；角色部署阶段、重新部署、卸载及操作记录在对应项目详情中查看，部署操作结束后 FRP 页面继续展示连接清单。

frpc 部署只准备客户端程序，不生成虚构的目标连接或启动连接服务。frps 部署交付配置文件与独立的 systemd 运行载体；监听地址和控制端口由配置文件控制，不在部署弹窗填写。首次部署采用参考配置，重新部署沿用服务器已有配置，配置预览可查看实际值。完整部署成功后才开放连接选择，失败、部分完成或未知不计为新的完整部署。预览和确认使用固定输入，受理前配置变化须重新确认；受理后保存的新草稿不覆盖原操作快照。

“新增连接”分别选择已部署 frpc 客户端和已部署 frps 服务端的服务器。选项依据对应角色的完整部署参照，按已应用主机去重；草稿、部署未完成、已卸载、visitor 及仅有程序名称的占位记录不作为对应角色的可选依据。已停止但完整部署仍在的角色可以选择。缺少任一角色时提示先部署并禁用保存；保存时重新核对部署状态，拒绝失效或不匹配的选择。

frps 地址、管理身份与架构来自所选服务器，监听地址与控制端口取自其已部署配置，在连接表单中只读。保存只创建连接草稿；从连接详情明确应用配置后才启动对应的 frpc 连接服务，复用已部署程序。同一对服务器不重复建立连接；多个客户端可以共用同一个 frps 运行载体，客户端及 visitor 按连接生成独立文件和 unit。共用 frps 的代理名、TCP 端口及同机 visitor 端口须避免冲突。已部署连接不能通过编辑隐式换机。

连接卡片只保留“查看连接与映射”和“编辑连接”，以两端服务器名称标识关系，分别展示 frpc 地址、frps 控制地址及角色状态。新连接区分“frpc 已部署”和“连接配置待应用”；完整应用后展示运行状态及配置差异。未部署或已卸载角色不显示“不适用”的运行状态。角色运行中不代表隧道或代理已连通，仍显示“连通性待核对”。

STCP 连接额外展示与 frps 同机的 visitor 状态。移除最后一条 STCP 映射后，已有 visitor 载体仍在卡片中显示，需单独处理。

汇总展示连接配置数、去重后的 frpc／frps 服务器数及 TCP／STCP 映射数，按当前清单计算，不统计为已部署或可用连接。

卸载服务器角色前须处理已安装的关联连接客户端及 visitor；保留共享程序及其他角色。有关联连接时，重新部署不能隐式迁移监听、认证或运行路径。共用 frps 的认证修改须审阅全部已部署的关联角色，不能只更新一条连接而令其他连接继续使用旧认证。

部署确认、配置预览和执行结果仍为浏览器模拟，不连接真实服务器。
