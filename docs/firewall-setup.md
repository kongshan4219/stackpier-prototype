# 统一防火墙接入原型

本原型演示 Linux 64 位服务器统一采用 firewalld / nftables 的操作流程。发行版、服务管理器、恢复能力与已有规则由只读盘点识别；未核实能力时保留只读，不要求用户预先填写系统详情。模拟通过不代表正式实现或真实迁移验收。

## 状态与操作

| 状态 | 页面行为 |
| --- | --- |
| `ready` 可管理 | 显示 firewalld / nftables 及运行／永久配置一致，开放端口规则。 |
| `needs-setup` 待安装／迁移 | 展示当前管理方式，提供安装或迁移预览；规则只读。 |
| `blocked` 仅可查看 | 明确列出恢复机制、复杂规则或作用范围等阻止原因。 |
| `pending` 正在接入 | 显示同一原操作的阶段，禁止再次接入和端口变更。 |
| `unknown`，无未决操作：检查未完成 | 只读检查未取得完整证据，保留旧规则与采集时间，仅允许重新检查。 |
| `unknown`，有原操作：结果待核对 | 保留原计划、旧观测与恢复保护，只核对原操作或请求恢复；新盘点问题不覆盖原操作状态。 |

查看页面、切换服务器和刷新均不会安装或切换软件。现有入站规则可转换时保留；Docker、VPN 与其他软件规则保留其归属，工具可以继续存在。非入站主机规则、未知加载器或无法等价转换的内容应阻止自动切换，不能只迁移能解释的部分。

## 固定接入流程

1. 选择服务器并只读检查，展示系统／架构、服务管理器、当前管理方式和配置状态。
2. 新机器先明确选择初始入站默认策略 `ACCEPT`、`DROP` 或 `REJECT`，不预选；选择固定到目标 Zone 的 target，并在成功后保持。既有机器逐项展示原策略与目标策略；已有 firewalld 按各 Zone 原 target 保留，`default` 不等同于 `DROP`。
3. 预览固定服务器身份、原配置、规则、依赖、停用的主机管理服务／加载器、网卡／来源对应 Zone、保留范围与恢复方式，有效期五分钟。
4. 用户确认后记录一个操作，依序模拟复核、备份与独立恢复保护、安装配置、受保护切换、新 SSH 与两层配置核验。
5. 成功后保持规则和外部软件归属，才开放日常端口操作。失败模拟恢复原配置和服务并保存失败记录；恢复后的服务器仍未完成统一接入。

取消预览没有写入。服务器、配置、规则或默认策略变化使预览失效；执行中检测外部变化则保留结果未知，不盲目覆盖备份。刷新页面将执行中的模拟操作转为未知，继续保留主机冲突保护。核对和恢复沿原操作，不重新安装或重复迁移。

旧浏览器存储缺少统一防火墙观测时，保留原规则和历史，但初始化为 `unknown` 并禁止写入。只有新样例和明确加载的审阅场景能够预置已接入状态。

盘点问题按安全错误类型、检查阶段、对象路径／服务名、实际数量／限制和可重试性展示，不显示原始命令。未知类型使用通用说明；旧阻止原因与读取说明只做完全相同字符串去重，保留未结构化原因。重新检查通过后仍按实际条件决定待安装、待迁移或可管理，不因错误消失直接开放端口写入。

## 审阅场景

通过原型公共“试用场景”入口加载，切换前按已有机制提示重置演示数据；业务表单不新增故障注入选项。

| 场景 ID | 用途 |
| --- | --- |
| `firewall-ready` | 已统一接入，维护持久化端口规则。 |
| `firewall-multi-zone` | public / eth0 与 internal / eth1；新建与导入需明确选择。 |
| `firewall-migrate` | UFW 已有简单入站规则的受保护迁移。 |
| `firewall-install` | 新机器明确选择初始策略并安装接入。 |
| `firewall-blocked` | ARM / OpenRC 恢复能力未核实且存在复杂规则。 |
| `firewall-pending` | 执行中保留阶段及主机互斥，可完成演示。 |
| `firewall-failed` | 接入失败，恢复已核实。 |
| `firewall-unknown` | 原结果未知，核对仍缺证据，可以请求恢复。 |
| `firewall-recheck` | 原结果未知，随后取得新证据，沿原操作核实成功。 |
| `firewall-setup-error` | 接入预览失败：依赖来源、桥接与未证明双栈目标；无确认执行入口。 |
| `firewall-legacy-receipt` | 旧历史计划没有阶段诊断，按原记录展示并沿原操作恢复。 |
| `firewall-read-error` | 检查未完成：cron 访问失败、服务清单超限、启动入口读取变化；保留旧采集时间与规则。 |

## 组件与验证

- `firewall-state.js`：统一状态、主机写入条件、Zone 和只读盘点。
- `firewall-port-plan.js`：端口预览固定管理配置和 Zone，单 Zone 导出范围校验。
- `firewall-setup.js`：初始策略、固定计划、预览与受理。
- `firewall-setup-operations.js`：执行结果、核对、恢复及操作详情。
- `firewall-scenes.js`：审阅场景注入，不进入正式产品实现。
- `firewall-setup.test.mjs`：安装策略必选、固定目标、阻止条件、取消、成功、失败、未知、恢复、外部漂移与多 Zone。
- `firewall-boundaries.test.mjs`：逐 Zone 策略、单条／批量的配置漂移、历史范围、跨 Zone 导出和旧存储安全初始化。

完整组件回归 273 项通过，独立边界复验 12 项通过；统一防火墙 109 项浏览器检查与 56 项上下文回归通过，已复核桌面和手机截图。真实安装依赖、系统兼容性、默认策略转换、远端备份／恢复和重启持久化未在原型中执行。

以上为既有统一接入版本的验证结果。本次盘点错误表达经完整组件测试 276 项、统一防火墙浏览器检查 115 项通过，包含 1440／390／320 像素的检查失败场景；已复核窄屏截图。结果仅代表原型模拟，不替代正式接口或真实系统验证。

浏览器脚本为 `tests/browser-unified-firewall.mjs`：通过 `STACKPIER_PREVIEW_URL` 指定回环静态服务，`STACKPIER_SCREENSHOTS` 指定 `/srv/cache/stackpier-tmp/` 下任务目录，`STACKPIER_PLAYWRIGHT_MODULE` 指向主仓库锁定的 Playwright 模块，`CHROMIUM` 指定浏览器；`TMPDIR` 使用约定缓存。验证结束后关闭本任务服务，保留必要截图。

接入预览新增阶段诊断：直接失败与连带检查分开，依赖失败不显示无需安装；未证明双栈策略显示未核实／尚未确定。失败标题为“接入检查未通过”，隐藏确认框和执行按钮，重新检查须重新确认。该阶段 278 项组件、127 项浏览器检查通过；仍仅为原型模拟。

失败预览补充只读接口拓扑表，显示真实类型、双栈地址／路由计数与“尚未证明”的归属；不通过名称推断 Docker 所有权，也不因取得拓扑观测开放接入。新增表格已纳入失败场景的组件和浏览器断言。

历史计划缺少阶段诊断时使用中性提示，显示原记录的策略，不要求重新生成预览；核对和恢复仍沿原操作。当前完整组件 279 项、浏览器 130 项通过，包括旧回执审阅场景与恢复不新增操作。
