# 公共部署配置

部署配置组装 Compose / systemd 正文及附带文件映射；保存只更新公共配置修订，不执行部署。

## 编辑与详情

编辑器分成“附带文件映射”和“部署正文”。正文按原样保存，不解析或替换 `{{name}}` 等变量；普通样例使用明确内容，部署其他项目时须先自行核对正文中的名称和路径。FRP 专用结构化流程仍独立维护。

每项映射包含逻辑文件选择、架构规则、固定内容修订、目标绝对路径、“查看文件”与“移除引用”。最多 20 项；移除只解除配置引用，不删除公共文件。

文件详情使用独立抽屉，保留底层编辑器 DOM。映射选择区域可上传新文件；保存或取消上传都返回原编辑器。正文与其他映射不丢失。取消配置编辑、重复打开及刷新可恢复该配置的未保存草稿，保存后清除编辑缓存。

配置卡片的文件数量和关联项目数打开只读详情。详情可切换公共配置历史修订、查看固定映射与关联项目，编辑公共配置使用独立按钮，并说明影响范围。

## 固定修订与校验

映射保存 `groupId` 和 `pins: [{fileId, revision}]`，不靠名称匹配。架构规则可为自动匹配、仅 x86_64、仅 aarch64 或通用。默认固定所有已选变体当时的修订；新修订/新变体需要明确更新，保存配置不会隐式跟随最新文件。

保存时拒绝缺失文件/修订、0 B 或占位文件，以及相对路径、重复目标路径、根目录、末尾斜杠、空路径段、`.`、`..`、控制字符或超过 4096 UTF-8 字节的路径。不同架构能否匹配在目标服务器选定后检查。

## 部署与项目采用

选定配置、服务器、项目名后展示落点预览：公共配置修订、匹配架构、内容修订和身份、主部署文件路径、附带文件源名称与目标文件名。缺失架构、无效文件、主文件/附带文件路径冲突及环境缺失阻止继续。已登记目标重叠显示可能覆盖提示，不宣称真实检测过服务器目录。

只有明确执行模拟部署后才建立在途项目；成功后形成已应用快照。公共配置保存和文件替换仅产生更新提示；查看差异后“采用到项目草稿”只改变当前项目，应用需另行确认。

采用文件新修订可以形成不同于公共配置固定映射的项目独立草稿，公共配置本身仍保留原固定修订。配置修订、项目 D 草稿修订、A 应用修订不是同一个计数。

完整示例：`catalog-config.yaml` → Go 应用配置 → `catalog-api` → `/srv/stackpier-demo/catalog-api/app.conf`。源文件名与目标文件名分别显示。report-worker 的独立目录映射明确显示为项目/历史映射，不能当作当前公共配置的原样副本。

模型与验证详见 [资产版本联动](asset-linkage.md)。实际文件传输、远端读写与部署后端未实现。
