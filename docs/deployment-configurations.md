# 部署配置

## 文件映射

“新增部署配置”和“编辑部署配置”弹窗底部提供文件映射。每一项包含：

- 文件：下拉框按逻辑文件名列出可部署文件；同名的通用版本和不同架构版本合并为一个选项，并显示适用范围。
- 目标绝对路径：文件在目标服务器上的完整路径，例如 `/srv/example/path/file`。

可以添加和删除多项映射，单个部署配置最多 20 项。没有映射时仍可保存部署配置；任一行只填写一侧时不能保存。

目标路径必须是规范的 Linux 绝对文件路径，包含文件名，且不能是根目录、以 `/` 结尾、包含空路径段、`.`、`..` 或控制字符。路径 UTF-8 编码长度不超过 4096 字节。同一配置中的目标路径不能重复，避免多个文件覆盖同一位置。同一个文件可以映射到多个不同路径。

不可部署的占位记录不进入选择列表。用户上传的空文件是有效的通用文件，可以参与映射。已保存映射引用的文件不再可用时，编辑弹窗会显示缺失状态，重新保存前必须处理。

## 架构与部署

映射保存逻辑文件名，不固定某条文件记录。部署项目或采用公共配置时，映射随配置进入项目草稿；执行部署、应用或文件更新时，再按目标服务器选择文件。可识别的 ELF 优先匹配目标架构，没有架构专用版本时可以使用同名通用文件；两者都没有时拒绝操作。

操作受理时固定本次使用的文件身份、适用范围和目标路径。受理后替换文件或新增优先级更高的架构版本不会改变在途操作的输入；操作完成后如已有更新，项目仍显示文件可更新。

修改公共部署配置只给关联项目增加更新提示。项目需要明确采用新修订，文件映射才进入项目草稿；之后仍需单独应用。保存配置本身不会传输文件或执行部署。

项目“配置”页不把部署配置或本地草稿冒充为服务器现状。该页读取并只读展示服务器上的 systemd / Docker Compose 文件及映射目标文件；部署配置仍作为后续部署输入单独维护。

原型只保存并展示映射关系，实际文件传输和远端路径写入仍是正式后端的待实现范围。
