# 防火墙端口规则原型

当前原型收敛为 firewalld 主机服务与入站端口管理。状态卡提供启停及开机启动确认；Docker Zone 不可编辑，其他软件规则不迁移。旧接入场景仅保留历史演示。服务变化为浏览器模拟，不代表真实 SSH 或恢复验证。

防火墙统一采用 firewalld，以 nftables 为底层。页面沿用栈桥导航、服务器选择和端口表格；其他工具只用于诊断，不提供后端切换框。安装、迁移、失败与恢复见[统一接入](firewall-setup.md)。全部行为是浏览器模拟，不连接服务器。

## 页面与规则操作

- 服务器状态区区分可管理、待安装／迁移、仅可查看、正在接入和结果待核对。刷新仅模拟只读盘点，不安装、启用或切换软件；读取失败保留旧规则与原采集时间。
- 只有 firewalld / nftables 已接入、运行与永久配置一致、连接可信且没有未完成主机防火墙操作时，开放规则写入。
- 规则表仅展示选定服务器的主机入站规则，包括协议、端口／范围、Zone、使用状态、允许／拒绝、来源、描述和操作；支持搜索、策略筛选、分页和勾选。待接入显示原管理方式及只读来源，成功后才标记 firewalld 持久化规则。
- 创建／编辑包含固定服务器、Zone、TCP / UDP / TCP+UDP、IPv4 / IPv6、所有或指定来源、允许／拒绝及描述。多个 Zone 不默认选择 public；编辑不能移动服务器或 Zone。
- 规则的 Zone 不明确或已从观测中消失时，条目只读并说明原因，不能勾选、修改、删除或导出。
- SSH 管理规则只读，拒绝规则不能覆盖管理端口。已有规则不要求栈桥归属。监听状态与规则策略、网络可达性分别表达。
- 编辑、删除、批量操作和导入先展示固定差异，再确认提交；确认与历史始终显示固定 Zone。预览固定服务器、管理器、配置状态及所有 Zone 的绑定和 target；受理、执行与结果核对再次校验，变化后不能沿旧意图报告成功。
- 取消不执行；明确失败不改规则，响应未知保留原操作与核对入口。同机未完成操作与规则写入互斥。
- 原型审阅场景负责注入成功、失败、断连与恢复证据；防火墙业务表单不提供结果下拉选择。历史操作继续可读。

## 导入与导出

沿用 `stackpier-port-rules` 版本 1 的 JSON，每次最多 50 条、256 KiB。导入必须选择目标服务器与明确 Zone，整体校验版本、字段、地址族、来源、重复和管理通路冲突后生成固定预览。

导出选中项；没有选择时导出当前筛选结果。一次只能导出一个明确 Zone，跨 Zone 或未知范围会阻止并提示勾选同 Zone 规则。文件名包含 Zone；正文只包含协议、端口、地址族、来源、策略和描述，不包含凭据、运行状态、服务器身份、Zone 绑定或命令。导入时重新选择 Zone，不把不同作用范围无条件合并。

## 实现与验证

`assets/features/network/firewall.js` 负责页面／编辑，`firewall-transfer.js` 负责导入导出／批量确认，`firewall-port-plan.js` 固定管理配置与 Zone，`shared.js` 维护规则校验与模拟结果，`firewall.css` 维护局部样式。接入状态与迁移组件见[统一接入](firewall-setup.md)。

完整 273 项组件测试通过；独立复审发现的 Zone 固定、确认展示、导出范围和旧存储问题已修复并复验。`browser-unified-firewall.mjs` 的 109 项真实浏览器检查通过，覆盖 1440 / 390 / 320px、固定预览、策略选择、Zone、导入／导出边界、取消、失败／未知与恢复；`browser-operation-context.py` 的 56 项上下文回归通过。保留本轮截图，模拟结果不转记为正式执行验收。

组件测试只证明浏览器模拟逻辑；正式 firewalld 写入、持久化、多架构执行器、规则迁移与真实服务器验收由主仓库分别设计和验证。
