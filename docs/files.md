# 文件

## 上传与分类

1. 点击“上传文件”，弹窗内只提供文件选择区域，也可拖入单个文件。
2. 选择文件后读取完整内容并计算 SHA-256；可识别的 ELF 程序自动记录架构，其他内容记录为“通用”。
3. 点击“保存”进入文件名确认，默认使用所选文件原名，可以修改。
4. 点击“确认保存”才写入浏览器演示记录；返回上一步保留分析结果，关闭弹窗不保存。

文本、配置、证书、压缩包、媒体和其他类型都可以保存。空文件也作为通用文件处理。格式异常、架构未知或不是可执行类型的 ELF 文件仍可作为普通文件映射，但不会被当作 systemd 主程序。

可识别的 ELF 文件按架构区分；不同架构可以使用相同文件名。通用文件是独立的适用范围，同名通用文件冲突时需通过列表中的“替换文件”更新。架构专用文件和通用文件同名时，部署到对应架构会优先使用架构专用版本，其余架构使用通用版本。

SHA-256 相同的内容只保留一份，即使改名也不能重复保存。选取文件和最终确认时均检查去重。

## 替换与失败处理

- 替换保留文件归属和记录 ID，默认文件名仍取新选择的原名。
- 替换必须保持适用范围：架构文件不能换成通用文件，通用文件也不能直接换成某个架构的 ELF；另一范围通过上传新增。
- 文件名不得占用其他记录在同一适用范围下的文件名或逻辑名称。
- 替换相同内容提示无需替换。目标记录在弹窗打开后变化时拒绝覆盖。
- 文件读取、摘要计算或存储失败时不改动原记录。分析期间重新选择或关闭弹窗，旧结果不能回写。
- 文件名不能为空，不允许路径分隔符、控制字符、`.`、`..`，UTF-8 编码长度不超过 255 字节。
- 保存只提示实际引用该文件的项目有更新，不自动部署，也不保留独立的历史文件回退库。

## 原型验证范围

原型真实读取用户选择的文件并计算摘要，但不上传、不执行，也不持久保存文件内容。当前站点的 localStorage 只保存名称、大小、类型、适用架构、摘要和演示记录。

ELF 架构识别支持 x86、ARM、MIPS、PowerPC、s390x、RISC-V 和 LoongArch 的已知组合。ARM 32 位只记录为 `arm` 或 `armeb`，不推断具体指令集版本；识别架构不代表文件可以运行。

浏览器单次分析上限为 256 MiB，超时为 30 秒；SHA-256 使用 Web Crypto，需要 localhost 或 HTTPS 环境。原有虚构样例没有真实内容，不能为其伪造摘要，替换后才建立真实摘要。

去重和记录一致性验证只覆盖浏览器演示，不代表正式后端的文件存储、权限、传输或多用户并发实现。

文件头字段和机器类型参照 [ELF Header](https://gabi.xinuos.com/elf/02-eheader.html) 与 [Assigned Machine Values](https://gabi.xinuos.com/elf/a-emachine.html)；摘要接口参照 [Web Cryptography](https://www.w3.org/TR/webcrypto/)。
