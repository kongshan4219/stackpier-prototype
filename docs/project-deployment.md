# 项目服务与统一部署

项目只表示已部署的服务实例，运行、停止、异常和暂时不可达都保留。未执行的表单和成功卸载的对象不属于项目；现有服务的配置草稿仍可保存。

## 部署

入口为工作空间 / 项目 → 部署项目，先选择运行类型，再填写目标服务器、服务名称和部署配置。详细交互见[部署配置选择流程](deployment-config-selection.md)。单服务器筛选继承目标；全部服务器视图必须选择，离线或待核对不自动换机。FRPS、FRPC、visitor 同样只选择保存好的角色配置。

表单、项目副本编辑与落点预览均为临时输入，不建立实体或预占名称。取消、返回、打开详情、重复打开及刷新保留非敏感输入，但不会创建未部署项目。项目名在同机已部署实例及受保护的在途资源中检查，不用历史卸载名称永久占位。

正文和文件统一在部署配置编辑；预览可展开已保存正文和全部落点，首次部署不提供临时正文副本。Compose 显式变量随配置固定，原型不执行变量展开。已知路径、端口、架构和固定引用冲突阻止执行，不宣称理解任意脚本。

新 systemd 配置使用[服务文件正文与文件／目录映射](deployment-configurations.md#systemd-正文与映射迭代)，预览保留原样正文、映射路径与目录删除规则，成功按 systemd 运行状态设计，业务健康以后单独配置。映射不能覆盖已知 unit、项目私有目录或其他项目映射；模拟失败清理和卸载保留外部映射目标。旧固定程序配置及项目继续按原参照展示。

确认执行只创建操作记录，固定输入、服务器身份和修订，展示逐步进度。全部模拟成功并核对才创建一个项目，重复完成不会重复创建。失败、部分完成、结果未知保存在显著的待处理操作与失败记录中，保留输入、日志、残留范围和恢复入口。未知先核对原操作；全部成功的原部署可以在明确核对后建立实例，旧失败证据保留。

FRPS 先部署监听服务；FRPC 配置引用已部署 FRPS；visitor 配置引用已有 STCP 连接，部署目标须为对应 FRPS 主机。visitor 使用 frpc，没有虚构程序资产。0 B、缺架构、失效程序引用及主机状态阻断不能通过模拟成功绕过。

## 完全卸载

卸载确认逐项列出服务 / unit 或容器、配置、映射、独立目录、已登记的专属卷及数据；明确告知数据删除，需确认清理范围和项目名。不提供默认保留数据的卸载。

所有必需项目专属清理项成功并核对后才移除实体、解除关联。公共文件 / 配置、共享 FRP 程序、共享卷、外部挂载、DNS / 防火墙条目保持；防火墙关联只解除本项目并保留历史，不等于独占；DNS 独立管理，不参与项目关联或清理。共享 FRPS 被相关已部署服务使用时阻止清理。

归属不明、危险目录或其他引用阻止相应清理。按登记的资源边界检查，不凭相邻路径推断资源归属，也不解析任意 Compose / 脚本以猜测卷归属。外部目录不会递归删除。

项目资源归属台账按稳定项目 ID、类型与路径追加，保留每次交付来源。新增目录外独占映射、被替换的旧文件和部分 / 未知交付的可能资源均保留到确认清理；不会用最新配置覆盖旧清单。执行中归属变化、共享 / 外部资源位于递归目录内均阻止完整清理。

清理完成通过 cleanupOf / resolvedBy 关联原失败；原始失败状态保留，只从待处理计数中排除已完整核对解决的操作。旧版卸载遗漏的历史交付资源转为漏项待核对操作，不复活项目。

清理失败 / 部分完成仍保留项目和残留清单，继续清理只处理未确认成功项。未知须先确认原执行不会继续写入。操作日志保留，成功卸载对象不作为可管理项目出现。

## 旧状态迁移

迁移不改全站版本，不清空 localStorage。未部署独有配置保存在核对证据；纯 FRPC 程序准备转为安装元数据，稳定服务引用保留。成功且能证明完整清理的旧卸载移除；旧保留数据卸载转为待处理清理记录，归属先核对、清理另行确认，不复活项目。失败和未知对象保留原输入，无法可靠判断不猜测已清理。

迁移幂等，服务器、公共资产、FRP 配置、Cloudflare、DNS、防火墙和历史不重置。验证与边界见[本轮验收](service-lifecycle-validation.md)。新增五项回归及迁移证据见[清理与 FRP 修复](cleanup-frp-repairs.md)。全部行为仅浏览器模拟，未删除任何真实数据。
