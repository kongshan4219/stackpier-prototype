# 部署项目

“项目”页面和工作空间首页提供“部署项目”入口，部署配置列表也可以使用指定配置发起部署。

弹窗只包含三个字段，依次为部署配置、目标服务器和项目名。端口、环境变量、文件映射、运行方式及其他部署内容均取自所选部署配置。提交后先显示配置修订、匹配文件架构/修订/身份与目标路径的落点预览。预览本身不创建项目；明确执行模拟部署后建立临时项目并发起操作；部署中不进入项目列表，成功后加入并正常运行。不提供只保存而不部署的分支。

项目名须以英文字母开头，只能包含字母、数字、`-` 和 `_`，长度不超过 63 个字符。项目名在同一服务器内必须唯一，包括未部署或已卸载的保留记录；不同服务器可以使用相同项目名。

服务器、配置或项目名无效时不创建项目。落点预览先检查环境、文件、架构、端口和路径；执行时再次校验，避免过期预览绕过阻塞。已有项目更新或再次部署失败，不删除原来已经建立的项目。

## 失败记录

首次部署明确失败、部分完成、结果未知，均移出项目列表，归入“项目 → 失败记录”。前置检查拒绝也保留记录，标为“部署未开始、无需清理”。失败记录保存项目名、原服务器身份、部署配置、失败原因、原部署操作和残留范围。

刷新时仍在执行的新部署按结果未知处理，同样归入失败记录。旧浏览器状态中可识别的首次部署失败也会归档；缺少原服务器身份的历史记录只展示，不猜测清理目标。核对原操作不会自动将失败项目重新加入列表。

失败记录不占用项目名，允许同机同名重新部署；尚未结束的原部署或清理操作仍保护相同资源，不能重叠执行。

## 残留清理

“清理残留”展示部署受理时固定的范围，包括 systemd 服务或项目容器、运行定义文件、映射文件和项目数据目录。确认后模拟停止并移除运行实体、删除归属本次部署的文件与数据，再核对结果。后续编辑部署配置不改变旧记录的清理范围。

清理前检查原部署是否结束、服务器身份和连接、其他项目对相同路径的使用情况。结果未知时先核对原操作；被其他项目使用的文件或数据不能通过旧失败记录清理。共享镜像、外部数据卷和其他项目的数据不在清理范围内。

清理成功标为“已清理”，记录和操作历史保留。失败、部分清理及结果未知继续保留残留范围；重试只处理未确认清理的分项，结果未知的清理须先核对。服务器有未清理的失败记录时，不允许删除其连接记录。

以上都是浏览器模拟，没有真实 SSH、文件删除、容器移除或数据清理。
