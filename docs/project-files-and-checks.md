# 项目文件与巡检

## 服务器文件

项目详情的“配置”页是只读的服务器文件视图，不提供项目内配置编辑：

- systemd 项目读取对应的 `/etc/systemd/system/<项目名>.service`。
- Docker Compose 项目读取对应项目目录下的 `compose.yaml`。
- 已部署的文件映射按目标绝对路径读取，展示服务器文件名、类型、适用架构、大小和内容身份。
- 任意类型的映射文件都可以展示；二进制文件不尝试按文本预览。
- “重新读取”只刷新当前服务器观测，不修改部署配置，不下发文件，也不启停服务。

服务器不可达时保留最近一次可确认的文件快照，并明确标记读取失败。尚未部署和已卸载的项目不把部署配置草稿显示成服务器文件。

原型不会建立 SSH 连接，页面使用虚构观测数据模拟上述交互。正式实现由后端读取服务器文件，并为每次结果记录服务器、路径、读取时间和失败原因。

## 项目检查方式

每个项目一次只选择一种检查方式：

- systemd 项目可执行对应的 `systemctl is-active <项目名>.service`，或检查指定 HTTP 地址。
- Docker Compose 项目可针对对应 `compose.yaml` 执行 `docker compose ... ps --status running`，或检查指定 HTTP 地址。
- 选择 HTTP 时必须填写完整的 `http://` 或 `https://` 地址。

TCP 端口检查不再出现在项目巡检设置中。检查仍只记录结果和发送通知，不自动重启、修复或覆盖服务器文件。

## 已移除范围

项目详情不再提供“依赖与复制”页签，也不提供项目依赖通知、MySQL 只读副本初始化入口或对应试用场景。已有浏览器演示状态加载时会清理这些旧字段与旧复制操作。
