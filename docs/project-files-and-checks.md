# 项目文件与巡检

## 已应用配置与文件

项目“配置”页以正式 Web UI 的 `Projects.tsx`、`shared.tsx` 与 `ProjectFiles.tsx` 为对照，使用一张“已应用配置与文件”卡片和“固定版本”标记。它展示成功部署参照，不展示服务器文件正文、公共最新正文或项目草稿。

| 项目类型 | 固定信息 |
| --- | --- |
| systemd 旧固定程序模式 | 部署配置修订、服务器、服务、独占目录、程序和配置固定版本、成功条件；下方展示受管文件摘要核对。 |
| systemd 新正文模式 | 固定配置修订、服务正文、unit、文件／目录映射；默认按运行状态核验，业务健康未配置。映射内容未读取，摘要核对仅模拟 unit。 |
| Compose | 配置修订、服务器、项目范围、独占目录、固定配置摘要、服务 / 镜像 / 端口 / 环境变量名称 / 健康检查，以及已保存的固定文件、卷与网络范围。 |
| FRP | 配置修订、服务器、服务角色、项目身份、目录、程序固定版本、控制端点、管理接口、允许端口及成功条件；不提供普通 systemd 文件核对按钮。 |

原型沿用历史虚构数据；未保存的摘要、结构化服务信息和 FRP 管理参数显示未知，不以公共最新配置补齐，不生成虚构的成功摘要。已保存文本的 SHA-256 由浏览器计算，仅代表此模拟文本。Compose 样例单独保存固定服务摘要，旧浏览器数据缺少该字段时明确提示。

## 受管文件核对

“核对受管文件”只比较程序、配置和 unit 的摘要，不应用配置、不传输文件、不启停服务。首次进入显示“尚未核对受管文件”；核对中禁用重复请求。结果按路径显示状态、观测时间、远端摘要 / 已知大小、已部署参照摘要。

[新正文与路径映射模式](deployment-configurations.md#systemd-正文与映射迭代)仅从保存的正文计算 unit 摘要，按钮明确为“模拟核对 unit”。路径映射没有读取本机或远程内容，不生成映射文件摘要或一致性结论。

- 状态区分“一致”“远端被改”“缺失”“无法读取 / 无法确认”。
- 失败保留上次观测及原时间，明确标为“历史观测 · 已过期”；连续失败不丢失最后一次已知观测。
- 部署参照变化后，旧核对结果显示过期提示；核对中的目标或参照变化时丢弃迟到结果。
- 结果保存在当前浏览器。试用场景提供远端被改、缺失、核对失败；场景工具不进入正式页面。

## 草稿与更新入口

原型已有的公共配置差异、采用到项目草稿、正文预览与单独应用流程，移到“更多 → 项目草稿与更新”弹窗；FRP 原有读取、采用及连接定位也在该弹窗保留。此任务只对齐配置页，不把原型的通用采用流程冒充正式 systemd 的受控更新能力。

新正文模式暂不提供项目草稿、采用或应用入口，项目更新后续单独设计；公共配置保存可供新的部署使用，已有项目保留原部署参照。旧固定程序项目也不能通过采用公共新修订自动切换为正文模式。

版本模型详见[资产版本联动](asset-linkage.md)。原型不会建立 SSH 连接，页面结果不代表真实服务器状态或用户验收。

## 验证

组件回归运行 README 的全量测试；浏览器回归入口为 `tests/browser-project-configuration.mjs`，通过 `STACKPIER_PLAYWRIGHT_MODULE` 指定已有 Playwright 模块、`CHROMIUM` 指定浏览器、`STACKPIER_PREVIEW_URL` 指定回环静态服务，`STACKPIER_SCREENSHOTS` 指定符合主仓库规范的证据目录。无需给原型引入运行依赖。

本次通过 225 项组件测试和 65 项 Chromium 检查，覆盖 1440px / 390px 布局、三类项目、首次核对、变更 / 缺失 / 失败、刷新恢复、独立草稿弹窗、Escape 与焦点返回。截图：[桌面配置](screenshots/project-configuration/systemd-desktop.png)、[手机配置](screenshots/project-configuration/systemd-mobile.png)、[失败历史观测](screenshots/project-configuration/read-failed-mobile.png)、[Compose 固定信息](screenshots/project-configuration/compose-desktop.png)。

## 项目巡检方式

每个项目一次只选择一种检查方式：

- systemd 项目可执行对应的 `systemctl is-active <项目名>.service`，或检查指定 HTTP 地址。
- Docker Compose 项目可针对对应 `compose.yaml` 执行 `docker compose ... ps --status running`，或检查指定 HTTP 地址。
- 选择 HTTP 时必须填写完整的 `http://` 或 `https://` 地址。

TCP 端口检查不再出现在项目巡检设置中。检查仍只记录结果和发送通知，不自动重启、修复或覆盖服务器文件。

## 已移除范围

项目详情不再提供“依赖与复制”页签，也不提供项目依赖通知、MySQL 只读副本初始化入口或对应试用场景。已有浏览器演示状态加载时会清理这些旧字段与旧复制操作。
